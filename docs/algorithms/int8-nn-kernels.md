# Int8 NN kernels (generic reference)

**What it does:** the generic int8 inference kernels of the NN layer (ER-NN-KERNELS N1): `Dot`, `FullyConnected`, `Conv2D` (any kernel, stride, same/valid padding), `DepthwiseConv2D` (channel multiplier 1), `MaxPool2D`, `AvgPool2D`, `ReLU`, `ReLU6`, requantised element-wise `Add`, TFLite's int8 `Softmax`, plus per-channel requantisation (`Requant`, `QuantizeMultiplier`) and fused-activation clamp helpers. Pure Go, no allocation, TinyGo-buildable. It is also the bit-exact reference for the ESP32-S3 PIE kernels (N2) and the K210 CPU path.

**Where:** `x/math/primitive/qi8` (`quant.go`, `act.go`, `shape.go`, `dot.go`, `conv.go`, `pool.go`, `add.go`, `layer.go`, `impl_generic.go`); design and semantics in the package's `SPEC.md`.

**Two tiers (since review R3):** the free functions (`Conv2D`, …) are the always-generic exported **reference**. Prepared layer types (`Conv2DLayer`, `DepthwiseConv2DLayer`, `FCLayer`, `MaxPool2DLayer`, `AvgPool2DLayer`, `ReLULayer`, `ReLU6Layer`, all implementing `Op{InShape, OutShape, Run}`) validate once in `Prepare` (same errors as the free functions) and run many times; `Run` checks only slice lengths and returns `ErrNotPrepared` if fields changed after `Prepare`. Their inner loops go through a build-tag seam (`impl_generic.go` today; an `esp32s3 && !qi8generic` file adds PIE) with an optional caller-provided `Scratch` (`ScratchLen()`) for aligned/repacked weights; `Backend()` names the build. Contract: per-op CPU backends are byte-identical to the reference; whole-model offload (KPU) is outside this interface and compared within a tolerance. Tests: 7000 seeded cases / 1 027 872 outputs prepared vs free functions, 0 mismatches; 35-row Prepare error table; field-mutation detection; AllocsPerRun 0 for Prepare and Run; `-tags qi8generic` and 32-bit (`GOOS=linux GOARCH=arm go vet`) builds.

**ESP32-S3 PIE backend (ER-NN-KERNELS N2):** `impl_esp32s3.go` + `pie_esp32s3.c` (`esp32s3 && !qi8generic`). Conv2D and FullyConnected gather each receptive field into a 16-byte-aligned patch (padded cells = zpIn, zero tail to a multiple of 32) and run `qi8_pie_dot_rows` against weight rows repacked at `Prepare` (fused `ee.vmulas.s8.accx.ld.ip`, software-pipelined, `loopnez`); the zero point is folded as `bias − zpIn·Σw` (exact in wrapping int32). Weights may be packed in place (`W = InPlaceW()`, the aligned scratch start) so only one copy exists; a repeated `Prepare` restores the original layout before repacking, new weights are loaded with `Reset` → write `W` → `Prepare`, and a `W` misplaced inside the packed region is `ErrLength` (review R-NN-R3-N2 F1/F4, verify V-NN-R3N2-FIXES). The Go side also runs on the host under the test-only tag `qi8pieemu` (pure-Go models of the C kernels that assert their alignment and read-ahead preconditions; `make qi8-pie`). `init()` sets CPENABLE bit 3 (PIE is coprocessor 3; TinyGo enables only the FPU). Pools and activations are still generic (depthwise: next paragraph). On the chip (XIAO ESP32-S3, 240 MHz): 17 000 random Conv2D/FC cases, 2.5 M outputs per path (incl. in-place pack and misaligned scratch), **0 mismatches** vs the free functions. Conv 3×3 2.44 cycles/MAC (generic 19.7), pointwise 3.4–3.8 (generic ≈ 22). Benchmarks: `cmd/nnbench`.

**PIE depthwise (ER-NN-PIPELINE step 1):** `qi8_pie_dw_px` accumulates 16 channels per lane group in QACC (`ee.vmulas.s8.qacc`). QACC lanes are 20 bits and **saturate** at ±(2^19−1) (measured on the chip: 32·16384 clips to 0x7FFFF), so taps are summed in chunks of ≤ 31 and added in wrapping int32 — exact for any kernel size. QACC is spilled with `ee.st.qacc_{l,h}.{l.128,h.32}`: lanes 0–7 in QACC_L, 8–15 in QACC_H, packed as little-endian 20-bit fields (layout measured on the chip). When C is a multiple of 16 and the input is 16-byte aligned, groups load straight from the input through a per-pixel tap-pointer list (padded taps point at a zero-point row); otherwise each group is staged (16 bytes per tap). Bias folding `bias − zpIn·Σw` as for conv; requantisation runs in C with the same single exact rounding. On the chip: 11 200 random depthwise cases (kernels up to 7×7, non-square, strides 1–3, SAME/VALID, channels 1–33, aligned and misaligned inputs) within a 27 200-case run, 0 mismatches; depthwise 50.9 → 26.6 cycles/MAC in MobileNetV1-0.25.

**Element-wise Add (ER-NN-PIPELINE step 2):** `Add(dst, a, b, AddParams)` / `AddLayer` (two inputs, so not an `Op`): `y = clamp(round_half_away(((a−zpA)·MultA + (b−zpB)·MultB) / 2^(31−Shift)) + zpOut, Min, Max)`, `AddRequant{MultA, MultB, Shift}` = both real multipliers (`scaleX/scaleOut`) with a shared shift, from `QuantizeAddMultipliers`; one rounding of the exact sum, like `Requant`. The int64 definition is evaluated exactly in 32-bit arithmetic (Mult split at bit 16; derivation in `add.go`), which on the S3 cut Add from 115 (direct int64 loop) to 47 cycles/element; total shifts ≤ 16 (multipliers ≥ 2^14) use the int64 loop. Both builds run this generic loop: the same loop compiled by clang from C measured 49 cycles/element, and PIE has no element-wise 32-bit multiply. Tested against the exact big-rational reference (3000 cases incl. every shift, ties, near-zero-point inputs; a broken tie rule is caught) and on the chip (20 000 cases, 6.0 M outputs: FNV identical to the host run; layer = free function).

**TFLite rounding mode (ER-NN-PIPELINE step 4):** `Round` field on `Conv2DParams`, `DepthwiseConv2DParams`, `FCParams` and `AddParams`: `RoundExact` (zero value, unchanged) or `RoundTFLite`, which reproduces TensorFlow Lite's int8 reference Conv2D/depthwise/Add (double rounding) for imported models. `Requant.ApplyTFLite` = `MultiplyByQuantizedMultiplier` (int32 left shift, `SaturatingRoundingDoublingHighMul` with ties toward +∞, `RoundingDivideByPOT` with ties away); TFLite Add = `AddRequantTFLite{A, B, Out}` from `QuantizeAddTFLite(scaleA, scaleB, scaleOut)` with inputs shifted left 20; `Quantize6TFLite`/`ActReLU6TFLite` divide in float32 as TFLite does. **TFLite's FULLY_CONNECTED rounds once, half away from zero — `RoundExact`** (found against the interpreter: 150/150 cases; double rounding matched 129). Both backends honour the mode (PIE conv/FC requantise in Go, PIE depthwise in C `qi8_requantize_mode`). Tested against fixtures (`testdata/tflite_ref.json.gz`, generator and sources in `testdata/README.md`) that equal the **LiteRT 2.3.0 interpreter (reference resolver) bit for bit**: 150 each of Conv2D/depthwise/FC, 200 Add, 80 AvgPool, 300 Softmax cases, 200 ReLU6 ranges, plus 30 145 requantisations checked against the port — 0 mismatches, free functions and prepared layers; two broken tie rules (SRDHM nudge, RDBP threshold) are caught. The modes differ by 1 LSB near .5 ties: 0.07 % of conv/depthwise outputs with multipliers derived from float scales, 5.8 % with few-bit multipliers, up to ≈ 25 % at a multiplier of exactly 0.5. `AvgPool2D` already matched TFLite (no mode needed).

**Softmax and the zero multiplier (ER-NN-PIPELINE step 5):** `Softmax(dst, src, depth, SoftmaxParams)` is TFLite's int8 reference softmax (the TFLite Micro kernel) in gemmlowp fixed point (`exp_on_negative_values`, Newton–Raphson reciprocal; output scale 1/256, zero point −128), with `QuantizeSoftmax(beta, inScale)`; 300 fixture cases (7 824 outputs, incl. equal maxima and few distinct values) equal the LiteRT interpreter, 0 mismatches. `Requant{0, 0}` is now valid and means multiplier 0 — TFLite's encoding of a multiplier below 2^-32, which a real model (`vww_96_int8`, a dead channel with weight scale 1.8e-10) contains; the channel outputs its zero point in both modes and both backends.

**TFLite operators for detection models (ER-NN-commits-and-ops):** generic-only free functions, each derived from and checked against the LiteRT 2.3.0 interpreter (reference kernels; `tfliteops_test.go`, `testdata/tflite_ops.json.gz`, provenance `testdata/tflite_gen/OPS.md`): `Logistic` (TFLite's float32 table: `q = clamp(roundf(256/(1+expf(−s·(x−zp)))) − 128)`, a float64 table differs on 14 of 79 872 outputs), `Mul` (`(a−zpA)(b−zpB)` requantised; `b` broadcast cyclically: same length, per channel or scalar; `QuantizeMul` forms `sA·sB/sOut` in float32 as TFLite, float64 gets 2 858 outputs wrong), `MeanHW` (mean over H·W; 1/n folded into the multiplier with TFLite's integer truncation), `Requantize` (QUANTIZE int8 → int8), `Concat` (row interleave; LiteRT rejects mixed quantisation), `Pad` (constant value; raw copy) and `ResizeNearest` (TFLite's float32 index maths; a float64 version gets 87 outputs wrong). TFLite double-rounds Mul, Mean and Requantize (`RoundTFLite`); `RoundExact` is also provided and checked against the exact reference. Fixtures: 232 509 outputs over 1 502 cases, 0 mismatches; each wrong variant above is asserted to fail.

**LEAKY_RELU and RESIZE_BILINEAR (ER-NN-commits-and-ops, set 2):** `LeakyReLU` requantises `x − zpIn` with the identity multiplier when ≥ 0, else the alpha multiplier (both derived in float32 as TFLite: `inScale/outScale` and `(inScale·alpha)/outScale`; float64 gets 320 outputs wrong), double-rounded (`RoundTFLite`; `RoundExact` gets 2 577 wrong); alpha 0 and alpha > 1 supported, negative alpha is `ErrRequant` (`Requant` has no sign; TFLite's own tie results there do not follow its formula). `ResizeBilinear` is TFLite's `ResizeBilinearInteger` on raw values: 10-bit fixed-point scales and cell bounds, a four-term int64 sum, `(o ± 2^19)/2^20` (a single-rounding variant gets 1 219 wrong); align_corners with half_pixel_centers and upscales TFLite would read past the input are `ErrShape`. Fixtures (`testdata/tflite_ops2.json.gz`, interpreter-generated): 81 920 + 51 875 outputs, 0 mismatches; LeakyReLU exact mode vs the big-rational reference: 384 000 outputs, 0 mismatches.

**Semantics:**
- NHWC, batch 1. Activations int8 asymmetric (scale, zero point); weights int8, per output channel scale, symmetric or with a per-tensor weight zero point `WZP` (asymmetric weights of TFLite's uint8 models loaded as int8, ER-QU8: `acc = bias + Σ (x − zpIn)·(w − WZP)`, reduction bound `MaxTapsWZP` = 33 025; the generic kernels add `−WZP·Σ (x − zpIn)` once per output pixel (conv, FC) or use `w − WZP` per tap (depthwise) only when `WZP ≠ 0`, and the PIE backend runs such layers generically); bias int32 in accumulator scale. Conv weights OHWI, depthwise `[kh][kw][C]`, FC `[out][in]`. `Pool2DParams.TiesUp` gives TFLite's uint8 average pool (ties toward +∞ on the value − 128 form).
- `acc = bias + Σ (x − zpIn)·w` in int32; the reduction length is limited to `MaxTaps` = 65 793 so the sum cannot wrap (the bias term is the caller's responsibility). Every size is overflow-checked against `MaxElements` = 2^30 (fits a 32-bit int); violations return `ErrShape` before any slice is touched (`TestHugeShapesRejected`, `TestReductionLengthBound`, red first: a wrapped shape used to pass the length checks and `MaxPool2D` panicked). Padded taps contribute 0.
- Requantisation `Requant{Mult (Q31, [2^30, 2^31)), Shift ∈ [−31, 30]}`, real multiplier M' = Mult·2^(Shift−31): `y = clamp(round_half_away(acc·Mult / 2^(31−Shift)) + zpOut, actMin, actMax)`, computed exactly in int64 with **one** rounding (`RoundExact`); `RoundTFLite` uses TFLite's two-step SRDHM + RoundingDivideByPOT (above).
- Same padding as TensorFlow (out = ⌈in/stride⌉, pad before = total/2). Pools count only valid cells; `AvgPool2D` rounds the mean of the stored int8 values half away from zero (TFLite behaviour).
- `ActMin`/`ActMax` zero values clamp everything to 0 — set them with `ActNone`/`ActReLU`/`ActReLU6`.

## Completeness review

- Complete: no — no dilation, no depthwise multiplier > 1, no batched GEMM (1×1 conv covers per-pixel GEMM); the TFLite operators above have no PIE path.
- Tested: seeded random tests against an independent exact reference (dequantise to big.Float, compute, quantise with M', round half away, clamp): Requant.Apply 1 863 720 outputs over every shift; FullyConnected 2000 cases; Conv2D 3000; DepthwiseConv2D 3000 (half 3×3, stride 1/2); MaxPool2D and AvgPool2D 3000 each; ReLU/ReLU6 1000; Add 3000; exact-mode Mul 2000, Requantize 1500, Mean 1500; asymmetric-weight Conv2D/DepthwiseConv2D/FC 3000 (106 530 outputs); ties-up AvgPool2D 3000 — **0 mismatches**; the TFLite operators against interpreter fixtures (above). Hand-computed cases for each op, padding geometry with non-zero input zp, ±128/127 zero points, and every error path, incl. the `MaxTapsWZP` bound and its worst case.
