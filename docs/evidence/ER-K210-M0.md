**Camera contract** (proposal; the `esp32cam` peer's backend would implement the same exported API, so Leader routes it to them before code lands):

```go
// package sensor (no build tag): shared by every host
type Format uint8                     // Y8, RGB565, YUV422
type Resolution struct{ W, H uint16 } // QQVGA 160×120, QVGA 320×240, VGA 640×480
type Mode struct { Resolution; Format Format }
type Bus interface { ReadReg(reg uint8) (uint8, error); WriteReg(reg, val uint8) error } // one SCCB device per Bus
type Sensor interface { Name() string; Init(Bus, Mode) error }
func Probe(Bus) (Sensor, error) // reads PID/VER, returns the OV7740 or OV2640 driver

// package camera, camera.go (no build tag)
type Config struct { sensor.Mode; XCLK uint32 } // XCLK in Hz, 0 = backend default
type Frame struct { Width, Height uint16; Format sensor.Format; Seq uint32; Data []byte }
func FrameSize(Config) int

// package camera, one file per host (camera_k210.go now), identical signatures:
func Open(cfg Config) (*Camera, error)              // power, XCLK, SCCB → sensor.Probe → Init
func (c *Camera) Sensor() string                     // "OV7740", "OV2640"
func (c *Camera) Capture(buf []byte) (Frame, error) // fills the caller's buffer; no allocation
func (c *Camera) Close() error
```

- **No stub files.** On a host without a backend, `camera.Open` is undefined, so a firmware build for an unsupported host fails at compile time instead of failing at run time. Host builds and tests still cover `camera.go` and everything under `sensor/`.
- **K210-only extra:** the DVP's planar RGB888 output (KPU input) is `(*Camera).CapturePlanar(r, g, b []byte)`, defined only in `camera_k210.go`. Portable code doesn't call it.
- The shared types live in `sensor`, so `camera` → `sensor/ov7740` → `sensor` has no import cycle.
- **Build tags:** `k210` (TinyGo k210.json), `esp32s3` (esp32s3.json: `esp32s3 esp espradio`), `esp32` (esp32.json: `esp32 esp espradio`).

## 2. Design facts found while building (observed)

- **The target must inherit `maixbit`, not `k210`.** TinyGo 0.43 defines the K210 pins `P00…P47`, the FPIOA functions and the default UART/SPI/I²C pins only under `//go:build maixbit` (`src/machine/board_k210.go:1`, `board_maixbit.go:1`). A probe target inheriting `k210` with tag `unitv` fails: `machine_k210.go:427:16: undefined: SPI0_SDI_PIN`, `serial-uart.go:6:14: undefined: DefaultUART` (+ FPIOA errors). So `machine.LED` stays maixbit's D13; UnitV code uses `unitv.LED` etc.
- **The linker-script path is relative to the working directory**, not to the JSON file. With `"linkerscript": "probe.ld"`, building from the JSON's directory works; building from a subdirectory with `-target=../relld.json` fails `ld.lld: error: cannot find linker script probe.ld`. Hence `targets/unitv.ld` and "build from the repo root" (documented in `x/devices/unitv/doc.go`).
- No `flash-command` override: the inherited maixbit `kflash -p {port} …` is left; flashing goes through explicit `ktool` commands (M1), not `tinygo flash`.
