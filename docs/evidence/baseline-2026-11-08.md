# Host CPU baseline — 2026-11-08

[[index|Index]] · [[ER-001-reference-environment|ER-001]] · [[source-inventory|Source inventory]]

Owner instruction (verbatim): "properly update dndm, easyrobot projects so i can start improving on them". Roster task R1-05.

**Result:** the CPU numeric core (`x/math/graph`, `x/math/tensor/{types,eager,gorgonia}`, `x/math/primitive/fp32`, `x/math/mat`, `x/math/vec`, `x/iter`, `x/workers`) builds without CGO and its existing tests pass on darwin/arm64, also under `-race`, apart from the flaky `TestRRTStar_Simple2DGrid` in `x/math/graph` (its test sampler uses the global `rand`; about half of runs fail). The full tree does **not** build on this host: 33 packages need OpenCV (not installed), and 7 more fail in project code: 6 on darwin platform-file gaps (missing or drifted `linux`/`windows`-only files) and 1 on an arm64 gap (amd64-only assembly). Of 164 tested packages, 56 pass, 16 have failing tests and 11 fail to compile their tests; 81 have no test files.

## 6. Limits

- One host, one Go version (go1.27.2, newer than go.mod's 1.25). Behaviour on Go 1.25 is not verified.
- Vision (GoCV), TFLite, V4L2 and TinyGo/board targets are not covered; linux results are compile-only with `CGO_ENABLED=0`.
- Each test ran with `-count=1`; failing packages ran 3 times in total. Passing packages ran once, so other flaky tests may exist.
- No benchmarks, no `use_mt` build, no heavy tagged tests.
